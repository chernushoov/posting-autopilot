## Gaps / followups not in scope of this run

- Candidate 11 (operator's own /start) is left in the candidates table with `status='new'` and `vacancy_id=NULL`. Operator may want to delete it before the next pilot demo, since the operator is not a candidate. The bot's /start handler does not currently differentiate operator vs candidate.
- The patch in `_valid_tg_ref` (both sources.py and worker/tasks.py) accepts any 6+ digit numeric ID for `chat` destinations. There is no upper bound on safety — e.g. nothing prevents an operator from configuring another user's chat ID and posting at them. The reasonable next guard is "can the bot actually reach this user (i.e. has the user /start'd this bot)" — which is already enforced server-side by Telegram (it returns `chat not found`), but no operator-facing check warns ahead of save. Tracked but not closed in this session.
- Campaign 6 is left with `is_running=false`. It was triggered once via Run Now. Operator can either delete it, leave it for follow-up testing, or flip `is_running=true` to start the recurring cadence.
- Live Telegram delivery from the cadence loop (not Run Now) is not separately demonstrated. The Run Now path goes through the same `campaign_tick(...)` worker function, so it is covered by transitivity, but a clean recurring-tick test is a follow-up if needed.
